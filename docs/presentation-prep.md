# 발표용 준비사항 (12/8)

배포하지 않고 발표자 컴퓨터 한 대에서 서버를 실행해 데모한다. 발표 전에 아래를 준비한다.

## 0. 발표 조건 (과제 안내 요약)

출처: `OpenSWPlatform-Team Project (Final presentation).pdf`

- 일정: 12/8(화), 12/11(금). 팀당 11분 (준비 2분 + 발표 9분)
- 필수 내용: 각 페이지 설명, DB 설계, 데모, 오픈소스 라이선스가 있는 공개 Git 저장소 URL
- 데모는 라이브로 진행한다. 단계마다 DB 데이터가 바뀌는 것을 보여 준다. (예: Firebase 콘솔)
- 필수 시나리오
  1. A로 회원가입 → A로 로그인 → 상품 목록 → 상품 등록 → 로그아웃
  2. B로 로그인 → A의 상품 상세 → 그 상품에 리뷰 작성 → 로그아웃
  3. A로 로그인 → 리뷰 목록 → B가 쓴 리뷰 상세
- 팀 특화 시나리오: 경매, 구해요 등 특화 기능
- 평가: 교수 40%, 다른 팀 40%(최고점과 최저점 제외), 팀원 20%
- 다른 팀이 보는 기준
  - FE 사용성: 공통 템플릿 기반의 일관된 레이아웃, 쓰기 편한 입력 폼, 가독성
  - BE와 데이터: 페이지마다 고유 URL, DB 설계, DB 연결, 로그인 상태 유지
  - 요건 충족: 필수 8페이지 전부, 팀 특화 기능
  - 발표: 슬라이드 명확성, 발표자 태도, 필수 시나리오 완주, 9분 이내

## 1. 데모 사진

- 업로드한 사진은 서버를 실행한 컴퓨터의 `apps/fe/static/uploads/`에만 저장된다. Firebase에는 파일명(`img_path`)만 저장된다.
- [ ] 데모에 쓸 상품 사진을 정한다. (JPG, PNG, 5MB 이하)
- [ ] `apps/fe/static/uploads/`를 `.gitignore`에 추가한다.
- [ ] 데모 사진만 `git add -f`로 커밋해서 모든 팀원 화면에서 보이게 한다.

## 2. 데모 데이터

- [ ] Firebase의 테스트 데이터를 삭제한다. (11/22에 등록한 `맥북 에어 M2`, `자료구조 전공책`, `아이패드 1/2` 포함)
- [ ] 데모 계정을 만든다. (판매자 1명, 구매자 1명 이상)
- [ ] 데모 상품을 등록한다. 가격 정해진 상품, 경매 상품, 거래 완료 상품을 각각 1개 이상 준비한다.
- [ ] 데모 시나리오 순서대로 한 번 실행해서 필요한 데이터가 모두 있는지 확인한다.
- [ ] B 계정은 미리 가입해 둔다. A는 무대에서 가입하므로 같은 아이디가 Firebase에 없어야 한다.
- [ ] 모든 화면이 더미 데이터가 아니라 Firebase를 읽는지 확인한다. (약속 신청, 리뷰 포함)
- [ ] Firebase 콘솔을 다른 창에 열어 두고, 단계마다 어느 경로를 보여 줄지 정한다.

## 3. 메일 인증
